# Copilot handoff: SMART, Docker and file integrations

Use this document as the setup task on the Ubuntu LabDeck host. Work from this repository checkout. Before changing services, inspect the active Compose files, `/etc/labdeck/collector.json`, `systemctl cat` for LabDeck units, current mounts and numeric groups. Save a dated backup of configuration, units/drop-ins and the SQLite database using the existing backup procedure. Do not copy credentials into chat, logs or commands. Show the owner the discovered disks, Docker target names/Compose projects, and exact file share mount before enabling any optional control.

1. Run `npm run check`, the relevant repository tests, and `go -C collector test ./...` / `go -C collector vet ./...` where Go 1.24+ is installed. Build and install the collector as in [host collector setup](../../deploy/systemd/README.md). If a check fails, repair or report it; do not describe a skipped command as passed.
2. Configure SMART observations and the optional web-started test socket using [the SMART setup guide](copilot-smart-setup.md). Keep `/dev/disk/by-id` selection in root-owned configuration and keep the app container away from raw devices. Stop before initiating a real disk self-test and obtain the owner's approval for the exact disk/type and timing.
3. Configure Docker observation first, then the optional allowlisted controls as described in [host collector setup](../../deploy/systemd/README.md). Review each exact container name and each root-owned Compose file. Expose only `start`, `stop`, `restart`; do not use Compose `up`/`down`, `exec`, arbitrary commands, or mount the Docker socket into the app. Set the app-side allowlists to match the host allowlists. Test one noncritical reviewed target and verify the audit entry and next collector snapshot.
4. Configure share health, then the optional one-share file service using [the file setup guide](files-setup.md). Verify the exact mount and the service user's ACL. Enable only the chosen share ID. Test list, a temporary folder, a small upload/resume, collision rejection, rename and delete in that temporary folder. Never use real user data as a test target. Check that the app receives only the control socket through the existing collector-public mount.
5. Inspect `docker compose config`, the effective systemd units, permissions and app page states. Confirm status-only modes still work when each control service is stopped. Record actual test commands/results and unverified hardware, mount or Engine assumptions in a local validation note. Provide rollback commands for each optional service and Compose override.

The feature implementation is opt-in. No production host configuration is changed by this repository edit. Do not infer a disk's health from a self-test start response or infer a successful file write from an upload session start; verify later evidence.
