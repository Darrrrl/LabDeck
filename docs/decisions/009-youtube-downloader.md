# Decision 009: restricted YouTube library downloads

The owner explicitly approved this opt-in extension beyond monitoring-only V1. Downloads does not change Arr/Prowlarr monitoring. A separate unprivileged Python host worker receives only fixed prepare, submit, cancel, retry and status commands through a group-restricted Unix socket in the sanitized host mount. Library paths never cross the API. LabDeck receives neither library mounts nor upstream credentials. No Jellyfin control or library scan endpoint is added.

The worker stores normalized source IDs, frozen item manifests, bounded job states and publication journals in its own version-1 local SQLite database. Browser reads use a five-second server timer cache; only explicit preparation performs metadata extraction. One worker thread processes preparation and downloads serially, with at most 21 admitted active/waiting jobs (one executing plus 20 waiting), 200 playlist positions, a hard 100 GiB completed-media cap, conservative monitored source/conversion working-set checks, and a 24-hour attempt deadline. The unit additionally bounds individual file size. These checks are not a filesystem quota: cross-filesystem publication temporarily duplicates the complete output, and working-set polling can overshoot between checks. Ready previews and terminal jobs share a 100-entry/30-day retention pool. Restart interrupts uncompleted work; retry is explicit and skips completed and unavailable items. Unavailable playlist positions are never renumbered. A missing position is represented as unavailable when yt-dlp supplies a placeholder; genuinely omitted upstream positions cannot be reconstructed without upstream evidence.

All subprocesses use fixed argument arrays, clean environments, no ambient configuration/plugins, no cookies or remote code components, bounded extraction output, timeouts and process-group cancellation. Only exact public HTTPS YouTube watch, short-link and playlist URLs are accepted; persisted URLs/query strings and raw subprocess logs are prohibited. Live/upcoming entries are rejected at preparation when evidenced, and the download filter independently rejects them when flat metadata lacked the flag. FFmpeg always produces H.264/AAC MP4 (at most 1080p) or tagged MP3. This conservative re-encoding trades CPU for predictable actual output formats.

Publication copies complete media and generated XML into hidden `.part` files on the destination filesystem, then journals their inode/device identities durably before linking metadata first and playable media last with no-replace hard links. Paths are traversed through directory descriptors with `O_NOFOLLOW`. Cancellation never removes completed items. Restart rolls back journaled incomplete publication using inode identity, not blind path deletion. A metadata/media set is not a filesystem transaction; a brief metadata-only window is possible, but incomplete playable media is never exposed. Libraries must not have other untrusted writers or recursive importers that treat hidden `.part` files as media. Directory creations may remain after failure. The destination files are 0640, directories 0750, in a dedicated Jellyfin-readable group.

Root-installed nftables UID egress rules and systemd restrictions block private, link-local, loopback, host-local and reserved destinations, including redirected downloads. The narrow DNS exception uses only public resolver addresses on TCP/UDP 53, rather than granting broad loopback access. This is a mandatory installation security boundary, not protection supplied by URL validation alone. Installation, live network policy, Ubuntu filesystem permissions and installed YouTube/Jellyfin compatibility are separate unverified live gates; see [installation](../integrations/youtube-downloader.md).

Worker state and library media are separate from the LabDeck database and its backups. No existing LabDeck migration is needed. Stop the worker before a consistent state/media backup or restore; never restore state to replay completed work against different media without reconciling collisions.
