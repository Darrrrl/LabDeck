# Optional YouTube downloader

## Installation (Ubuntu; requires operator review)

Download only content you are permitted to save. Public videos and playlists only: no cookies, authentication, DRM bypass, arbitrary sites, subscription polling or Jellyfin control. Existing Jellyfin libraries must point to the configured roots. Each TV playlist is Season 01. See [decision 009](../decisions/009-youtube-downloader.md) for the trust boundary.

1. Create an unprivileged `labdeck-youtube` user with no login, a primary `labdeck-youtube-control` group for the socket, and a supplementary `labdeck-youtube-readers` group for media. Give only LabDeck's mapped UID socket-group access. Grant Jellyfin only readers-group membership; it must not gain socket access. Do not grant Docker or device access. Libraries must be local filesystems supporting hard links and directory fsync, without untrusted writers. Root-owned parent paths must not be writable by unrelated users.
2. Install Python 3.11+, FFmpeg with libx264/libmp3lame, Node 22+ in `/usr/bin/node`, and a reviewed current yt-dlp with its bundled `yt-dlp-ejs` into a root-owned `/opt/labdeck-youtube` virtual environment. Use `pip install 'yt-dlp[default]'` there as root; record the resolved package versions and hashes in your operator change record. Runtime downloads of JS components are disabled. Do not use an unsupported distro yt-dlp without validating the required flags. No dependency auto-update job is installed.
3. Install `deploy/scripts/labdeck_youtube.py` at `/usr/local/lib/labdeck/labdeck_youtube.py`, root-owned, non-writable by the worker. Copy `deploy/youtube.example.json` to `/etc/labdeck/youtube.json`, root-owned mode 0640 and readable by the control group. Set exactly three canonical absolute library roots, a local state directory outside all libraries, and the socket path. Create state directory mode 0700 owned by the worker. Give library roots worker ownership and readers-group ownership, mode 2750 (setgid); new directories inherit the readers group and files use 0640. For existing shared libraries use reviewed ACLs granting worker writes and Jellyfin reads, without granting Jellyfin media writes or control-group membership. Grant Jellyfin read/execute access, never world-writable access.
4. Create `/var/lib/labdeck-collector/public/youtube-control` owned by the worker, control group, mode 0750. Give the application container's mapped host UID access only to the control group as with existing host sockets. Keep the collector-public bind read-only; mount no media paths into LabDeck. Add `deploy/compose/compose.youtube.yml` alongside `compose.host.yml` in your existing Compose invocation, and set `LABDECK_YOUTUBE_CONTROL_GID` to the numeric control-group GID. The overlay sets `LABDECK_YOUTUBE_SOCKET_PATH=/run/labdeck-host/youtube-control/worker.sock`. Inspect the merged Compose configuration before recreating the app. Leave the overlay/socket unset to disable. Demo mode always disables mutations.
5. Install and enable nftables. Substitute the actual numeric worker UID in `deploy/youtube-egress.nft`; load this additive table and include it from the existing root-owned nftables configuration without flushing unrelated rules. Verify `nft list table inet labdeck_youtube` and the UID before enabling the service. The mandatory rules deny private/reserved/host-local destinations even on redirects and DNS rebinding; only public HTTP(S) and DNS to `1.1.1.1`/`1.0.0.1` are allowed. Create root-owned `/etc/labdeck/youtube-resolv.conf` with `nameserver 1.1.1.1` and `nameserver 1.0.0.1`. Do not allow an entire loopback/private subnet for systemd-resolved. If changing DNS, update only exact DNS addresses and ports; document the exception. Stop the worker when its UID/firewall policy changes.
6. Install `deploy/systemd/labdeck-youtube.service`. Add a root-owned drop-in with `ReadWritePaths=/srv/media/Movies /srv/media/TV /srv/media/Music` using the actual three roots. Update state/socket paths in the unit if changed in JSON. Confirm systemd IP filtering is supported on your Ubuntu kernel. Reload systemd, enable the service, and restart Jellyfin after group membership changes. Check socket permissions and that the worker cannot access Docker, home directories or private network services.

Network rules are a required deployment step, not automatically installed by Python. Do not run the worker outside the reviewed unit/firewall. Production remains disabled unless the socket is configured. Neither LabDeck nor the worker prints raw subprocess diagnostics. Worker errors are bounded categories; diagnose dependency/version/permissions using operator checks, not by enabling secret-bearing logs.

## API and outputs

Authenticated `GET /api/v1/youtube` returns cached `configured`, `available`, `observedAt`, and bounded jobs. Failed polls retain the previous successful observation time and jobs. `POST /api/v1/youtube` requires owner session, exact origin and CSRF; its strict command union has `prepare` with a media-kind request; `submit` with opaque job ID and optional music titles; or `cancel`/`retry` with only ID. Prepare returns an ID immediately; wait for the cached `ready` manifest before confirmation. URLs cannot include credentials, arbitrary query parameters, fragment, port or non-YouTube hosts. Only source IDs are persisted. Paths/user flags are never accepted.

- Movie: supplied name folder and same-name `.mp4`, plus same-basename movie NFO containing title and optional supplied year.
- TV: supplied show folder, `tvshow.nfo`, `Season 01/Show - S01E01.mp4` and matching episode NFO. Original playlist positions survive unavailable placeholders. Episode titles come from extraction; no invented external IDs or release dates.
- Music: `Artist/Album/01 - Track.mp3`, with embedded artist/album/title/track tags. Empty album input defaults to Singles; edit titles in the ready preview before confirmation. Sanitized preview names are authoritative.

Names reject traversal/separators/control characters and replace filesystem-reserved punctuation only in destination names; NFO/tag titles retain normalized supplied/extracted text with XML escaping. Existing media or NFO files are never overwritten. Publication rechecks collisions even if preparation passed. Failures leave no incomplete playable files; completed items remain on cancel/retry. Progress is stage/item state, not an invented percentage. Retry cannot fix unavailable/private playlist entries; create a new preparation for changed upstream contents. Prepared manifests are frozen; retry does not refetch the playlist or renumber items. A preparation timeout fails visibly; download attempts have a 24-hour deadline. State lists distinguish interrupted, failed and cancelled. One serial worker also prepares manifests, so preparation can wait behind a long download. The UI shows 20 jobs initially and expands older history on demand; ready previews expand automatically while other job items use accessible disclosure buttons. Worker responses are bounded at 64 MiB to accommodate the maximum retained manifests and escaped Unicode names, and requests remain at most 64 KiB.

## Maintenance and recovery

Stop the service before backing up `/var/lib/labdeck-youtube` including SQLite WAL/SHM as applicable, and back up completed media/NFOs separately. A LabDeck database backup includes neither. Worker database `user_version=1` has no LabDeck migration. Restoring older state against newer media intentionally causes collisions instead of overwrites. Reconcile state and media manually; do not delete existing media to force retries. Restart preserves completed items, rolls back uncommitted journaled publication, removes worker-owned staging directories and marks active jobs interrupted. Empty destination directories can remain. Terminal and ready records are retained for 30 days, at most 100 combined; active/waiting jobs are separately capped.

For dependency updates, stop the service, back up state/media, review upstream yt-dlp/FFmpeg security changes, update the root-owned environment, record exact versions/hashes, run fixture checks, then an authorized small public live download. Roll back the environment if flag/JS support fails; never silently enable plugins, cookie login, remote JS fetches or private-network access. No upstream availability guarantee is made.

## Verification

Fixture command: `python3 -m unittest discover -s tests/youtube -v`. API/contracts and UI checks use existing Vitest/Playwright tooling. Optional real codec/tag test: `LABDECK_YOUTUBE_FFMPEG_TEST=1 python3 -m unittest discover -s tests/youtube -v` with FFmpeg/ffprobe available. Live YouTube and Ubuntu checks are operator opt-in: prepare a permitted short video, confirm its movie output, probe format/codec, inspect NFO, repeat for a small playlist and music tags, verify cancel/retry and test firewall denial to private/host-local targets from the worker UID. Confirm Jellyfin scheduled scan recognition. These live checks are not satisfied by fixtures or a macOS run.

The opt-in CLI `python3 tests/youtube/live_check.py --socket /var/lib/labdeck-collector/public/youtube-control/worker.sock --kind movie --name 'Permitted smoke test' --source "$PERMITTED_YOUTUBE_URL"` prepares and displays relative destinations, then cancels without downloading. Run it only as an authorized socket-group operator after reviewing the installed firewall. Add `--confirm-download` only to explicitly authorize writing media into the configured production libraries; use a unique name, small permitted source and reviewed available disk space. This CLI exercises the installed worker, not the web authentication boundary. Interrupted/timed-out checks cancel outstanding work where possible. It does not automatically validate Jellyfin recognition or firewall denial; those remain operator checks.
