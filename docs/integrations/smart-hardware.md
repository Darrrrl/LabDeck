# SMART hardware compatibility and live gate

M7 fixture coverage includes ATA, NVMe and SCSI smartctl JSON, but hardware compatibility is not yet established. Run the live gate on the target Ubuntu machine before treating a disk as monitored. Some USB bridges, RAID controllers and HBAs do not pass through SMART, require a different `-d` type, or expose a controller rather than an individual disk. An `unsupported` state is honest missing evidence, not a healthy result.

Select only operator-reviewed whole-disk `/dev/disk/by-id/` symlinks. Record their stable IDs, model, protocol, size and suffix of serial locally, then confirm each configured path resolves to the intended block device. Never configure `/dev/sdX` enumeration or accept a path from the UI. The helper rejects non-block targets and any path outside that allowlist. Device replacement at the same configured ID is reported as a new identity when smartctl supplies a serial number; a missing serial leaves identity unknown.

For each disk, compare the sanitized snapshot to a contemporaneous local read using `sudo /usr/sbin/smartctl -a -j -n standby,3 -d TYPE /dev/disk/by-id/REVIEWED-ID`. Do not share raw output: it may include full serials or other sensitive identifiers. Verify health/exit status, temperature in °C, power-on hours, capacity in bytes, ATA reallocated/pending/uncorrectable sector counts, NVMe spare percentage/percentage used/media-error and error-log counters, or SCSI grown defects/uncorrected reads as applicable. Very large counters are represented as decimal strings, not JavaScript floating-point numbers. Missing attributes remain unknown; zero is a measured zero, never a stand-in for unknown.

The fixed read uses `-n standby,3` so a sleeping drive is skipped rather than intentionally spun up. Confirm it appears as `asleep`, retaining prior health evidence with its original timestamp. Validate a permission-denied device and an unsupported bridge if available; a timeout/read failure must also preserve last-good evidence without making it fresh. SMART's pass indicator is only current evidence and cannot predict survival. Temperature warning uses two readings at or above 45°C to enter and two below 42°C to clear; increasing error counters create bounded events. There are no self-tests, SMART setting changes, forecasts, control commands or folder scans.

The live gate must document the Ubuntu version, smartmontools version, controller/bridge type, reviewed systemd unit and directory permissions, observed snapshot freshness, and each supported/unsupported disk outcome. Use `npm run test:live -- --provider=smart` with the opt-in environment variables in the [systemd guide](../../deploy/systemd/README.md). That command reads only the sanitized snapshot; the separate manual comparison establishes device semantics. Until this is done, M7.4 remains pending.
